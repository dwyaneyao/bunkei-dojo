# 文型道場（考试复习工具）

和 `studio/`（按教材系统学习）分开的另一个工具：专门为班级考试复习文法。

## 网页版（手机也能用）

https://dwyaneyao.github.io/bunkei-dojo/

推送到 `main` 后，GitHub Actions 自动构建并发布（`.github/workflows/deploy.yml`）。网页版没有服务器：学习记录先存在打开它的那个浏览器里。

**账号同步**：「设置 → 账号与同步」用邮箱和密码注册／登录（Firebase Auth）。登录后，整份记录存在 Firestore 的 `users/{uid}` 文档里（gzip 压缩）。每台设备在登录时、作答停下几秒后、切到后台时，把云端记录合并进来，云端缺的再写回去（事务里做，两台设备不会互相覆盖）；另一台设备写入时会实时收到。代码在 `web/src/lib/cloud.ts`，Firebase 配置在 `web/src/firebaseConfig.ts`（这些值本来就是公开的；权限靠 Firestore 规则：每个用户只能读写自己的 `users/{uid}`）。不登录时，也可以用「导出记录／导入记录」手动合并（导入是合并，不会删掉作答）。

仓库里不放个人数据：`userdata/`（学习记录）和 `sources/`（原始照片）只留在电脑上，见 `.gitignore`。

## 在电脑上启动

双击 `Japanese Learning` 文件夹里的 `start-exam-review.bat`，或在 `exam-review` 文件夹里：

```bash
npm --prefix web run dev
```

浏览器打开 http://localhost:5179 。

想试功能又不想动学习记录时，用测试副本（端口 5180，数据存在 `userdata-sandbox/`，用完可以删）：

```bash
npm --prefix web run dev -- --mode sandbox
```

保存规则：浏览器和文件里的记录总是合并、不会互相覆盖（开两个标签页也安全）；记录文件读不了时，工具只提示、不写入。

## 题型分析与练法

目前的考试题型是「＿＿に書いて文を完成させてください」（给定文型，自己补内容）。得分要同时满足：接续、文型的意思和限制、上下文（时态、逻辑、语体）。所以每个文型有四种练习：

- 文型卡：意思、接续、用法限制、考场稳妥填法、常见坑、例句
- `form` 接续：打出连接后的形，自动判分
- `choice` 辨析：选最自然的填法，错项是常见错误并标注错因
- `produce` 完成句：考试式开放题，写完对照检查点和参考答案自评

复习间隔用 FSRS（与 studio 同一实现），不同文型交错出现；完成句错了会换同一文型的另一句再考。

## 加新课

在 `content/` 放一个新的 `lXX.json`，格式见 `web/src/types.ts`（`Lesson`）。应用自动读取；首页会列出格式问题（重复 id、选择题正确项不是一个、参考答案没用 `**` 标出填空等）。

- 文本里 `{漢字|かな}` 是注音，`**…**` 是填空部分，`＿＿` 是空格。
- 对话的说话人写成不带注音的 `A：` `B：` `母親：` `子ども：` 等，显示时会换行。
- 讲义原文只放在 `list` 里；其他说明、例句、题目都是自编。
